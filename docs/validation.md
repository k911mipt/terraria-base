# Полная проверка и порядок слияния

Часть #35 плана #24. Единственная полная команда, одинаковая локально и в Actions:

```sh
python tools/validate.py
```

Подготовка: Node.js 22 (`.nvmrc` закрепляет проверяемую в CI 22.16.0), Python 3.10+
(CI 3.12), `python -m pip install -r requirements-dev.txt`, затем
`python -m playwright install chromium`. На Linux могут понадобиться зависимости
через `python -m playwright install --with-deps chromium`. Все четыре Python-пакета
закреплены, включая транзитивные; сайт не загружает ни одного из них.

`python tools/validate.py --list` показывает фактический список этапов. Синтаксис
всех `js/**/*.js` и `tools/**/*.cjs` и все `tools/check-*.cjs` обнаруживаются
автоматически. Затем выполняются строгие строительный/сценический аудиты и три
реальные HTTP-проверки: запуск/взаимодействия, сохранённый кеш и проектный свет.
Новый checker или вложенный JS не требует копировать его имя в несколько workflow.
Геометрия и порядок данных этим обнаружением не сортируются.

Сбой процесса, таймаут или отсутствующая команда завершают запуск ненулевым кодом.
Следующий успешный этап не может скрыть предыдущую ошибку. `validation-artifacts`
содержит логи и `summary.json` попыток; `browser-artifacts` — PNG/JSON/trace.
Workflow сохраняет их при падении. Четыре регрессии самого runner проверяют
обнаружение файлов, ненулевой код, отсутствие исполняемого файла и успешный путь.

## CI и защита ветки

Работает один validation-workflow: `.github/workflows/validate-browser.yml`,
название `Planner validation`, стабильное имя job/check **`validate`**.
Он запускается для всех PR в `main` и push в `main`, без фильтра изменённых путей.
Старые дублирующие Jungle-workflow заменены, публикация Pages не изменяется.
Validation имеет только `contents: read`; все используемые actions закреплены SHA.

Порядок: PR → зелёный `validate` → завершённые Code/Security Review актуального
head → обработанные обсуждения → merge с ожидаемым SHA → post-merge CI и Pages.
Завершение комментария Codex не заменяет status check и наоборот.

**Защита `main` пока не включена этой интеграцией.** При проверке 7 сентября
2026 GitHub вернул `403 Resource not accessible by integration` для
`GET /repos/k911mipt/terraria-base/branches/main/protection`; доступные операции
коннектора не дают записывать правила администрирования. Это не отказ в записи
кода или создании/слиянии PR. Issue #35 остаётся открытой до настройки и проверки
блокировки падающего PR, успешного слияния и публикации.

Требуемая минимальная настройка после стабильного CI: изменения через PR,
обязательный check `validate` от GitHub Actions, без обязательного чужого approve
для одиночного владельца. Не отключать рабочие проверки и не обходить защиту.
