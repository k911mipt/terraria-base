# Браузерные проверки

Задача [#30](https://github.com/k911mipt/terraria-base/issues/30) из
[плана #24](https://github.com/k911mipt/terraria-base/issues/24).

## Запуск

Python 3.10+; Playwright нужен только тестам, сайт его не загружает.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
# Linux при необходимости: python -m playwright install --with-deps chromium
python tools/validate.py
```

Полная команда совпадает с Actions. Отдельные наборы:

```bash
python tools/check-browser.py
python tools/check-ui-rollout.py
python tools/check-lighting-browser.py
```

Каждый набор сам запускает HTTP-сервер на свободном loopback-порту, открывает
настоящие HTML и отдельные JS/CSS, затем закрывает сервер и браузер. Для уже
установленного Chromium предусмотрен `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.
Основной набор принимает `--artifacts`; по умолчанию это `browser-artifacts/`.
Локальный запрет HTTP-навигации браузером нельзя обходить или подменять inlining:
такой запуск не подтверждает настоящий HTTP, его результат берётся из CI.

## Текущий состав: 168 HTTP-сценариев

Основной `check-browser.py` содержит **144 сценария** для четырёх сцен:

| Группа | Число | Что проверяет |
| --- | ---: | --- |
| Нормальные desktop/mobile | 8 | Запуск, рисунок, таблицы и реальные действия пользователя |
| Сорванный startup / 404 JS / 404 CSS | 12 | Ошибка не маскируется статическим заголовком |
| Материалы | 36 | Неизвестные ключи/имена/краски, пропущенная спецификация, неверная палитра, подмена допустимым другим именем или проходимостью |
| Реестр рендереров | 16 | Неизвестный kind/style, удаление функции и замена не-функцией |
| Реестр рендереров тайлов | 16 | Удаление функций блока/стены и замена не-функциями до startup |
| Метаданные объектов | 40 | Размеры, комната, спецификация, цвет, сцена, выбранное имя/краска и несовместимое крепление |
| Вычисляемый аудит | 16 | Нарушения стен, размещения, состава жителей и воды при поддельном сохранённом PASS |

Отдельные **8 cache-rollout** сценариев проверяют переход со старым кешем общих
UI-файлов без request routing, отключающего кеш. Это тест существующего rollout,
не завершение полной политики транзитивных imports из #34.
Ещё **16 lighting** сценариев проверяют нулевой/чрезмерный радиус, удаление света
и блок внутри светильника. Browser/Node JSON и видимые статусы должны совпадать.

## Поведение и защита от ложного успеха

Слушатели исключений и ошибок обязательных ресурсов устанавливаются до навигации.
`#viewport[data-ready="true"]` появляется только после завершённого startup и
успешного первого кадра. Проверяются заполненные таблицы и разноцветные пиксели
обоих видимых кешированных Canvas-слоёв; размер PNG и заголовок не доказывают запуск.

Нормальные сценарии переключают все режимы и реальные кнопки, проверяют поиск,
историю камеры, mouse pan/wheel, мобильную шторку, настоящий touch pan и pinch
через Chromium CDP. Четыре вкладки проверяются в исходном HTML и реальным переходом.
Инспектор выбирает дверь, пустой тайл, неполный светильник, сундук, жидкость/резерв,
известный носитель экспоната. Проверяются модуль объекта и область тайла, крепление,
проходимость, идентичность установки, безопасность стены и повреждение данных
после запуска. Мутации восстанавливаются, текст диагностики не становится HTML.
Взаимодействия и рисование не должны заново вычислять полный аудит.

Стартовые мутации проверяют ожидаемую причину ошибки, видимую диагностику с
координатами, пустые таблицы и отсутствие даже временного ready. Строительные
нарушения, напротив, сохраняют работающий инспектор, но дают вычисляемый FAIL.
Результат сравнивается с той же чистой проверкой в Node, не с записанным статусом.

Внешние запросы считаются ошибкой. Необязательный HEAD-probe публикации изолирован
ответом 204 и записан отдельно; обязательные JS/CSS он не заменяет.

## Артефакты и ограничения

Desktop: **1800×1200**, mobile: **390×844**, DPR **1**, Chromium закреплённого
Playwright. Итоговый нормальный снимок: `visual`, `fit`, без выбора, мобильная
панель свёрнута. Для сценариев сохраняются PNG, JSON сетевых/консольных событий
и trace. Корневой `summary.json` описывает только 144 основных сценария;
дополнительные результаты находятся в `ui-rollout/` и `lighting/`.
При падении workflow загружает доступную диагностику и остаётся красным.

```bash
python -m playwright show-trace browser-artifacts/index-desktop-trace.zip
```

Это smoke-test, не универсальный визуальный golden: при рефакторинге дополнительно
сравниваются данные и снимки до/после в одной среде. Эмулированный touch не доказывает
работу физического iPhone/Safari. Ручная проверка: четыре вкладки, шторка, pan одним
пальцем, увеличение/уменьшение двумя, отпускание одного пальца, выбор двери и пустого
тайла. Pinch не должен оставлять случайное выделение.
