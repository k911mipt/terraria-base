# Браузерные проверки

Общая команда: `python tools/validate.py`. Node.js 22, Python 3.10+, закреплённый
Playwright из `requirements-dev.txt`; браузер устанавливается командой
`python -m playwright install chromium`. Сайт не загружает test-only зависимости.
В среде с установленным Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

## Наборы настоящего HTTP

| Команда | Сценариев | Назначение |
| --- | ---: | --- |
| `python tools/check-browser.py` | 144 | Четыре сцены, desktop/touch, реальные режимы, инспектор, навигация, отрицательные ресурсы/материалы/объекты/аудиты |
| `python tools/check-lighting-browser.py` | 16 | Нулевой/завышенный радиус, удалённые и заблокированные источники |
| `python tools/check-native-browser.py` | 8 | Нативные imports без глобальных compatibility aliases; независимость экземпляров и остановка |
| `python tools/check-ui-rollout.py` | 16 | Сохранённый кеш A→B, старый HTML, отрицательный контроль, offline/storage/ошибки manifest |

Всего **184 определённых HTTP-сценария**. Число определений — не свидетельство
успешного прогона: подтверждением служат логи/JSON конкретного CI head.

Сервер стартует на свободном loopback-порту. Слушатели исключений и ресурсов
устанавливаются до навигации. Ready проверяется вместе с заполненными таблицами
и фактическими непустыми Canvas-слоями; один видимый заголовок не означает startup.
Проверяется выбор двери, пустого и повреждённого тайла, разные режимы, фокус/назад,
mouse pan/wheel, touch pan/pinch и сворачивание панели. Аудит браузера сопоставляется
с CLI на тех же данных; испорченный сохранённый PASS не скрывает вычисленные ошибки.

## Нативные мутации

Старые короткие выражения мутаций работают через тестовый
`tools/lib/browser-probe.mjs`: только ответ стартового модуля в изолированном
контексте теста получает привязки к реальному экземпляру. Файлы приложения на
диске не переписываются; imports не удаляются. Исключения возникают в реальном
контракте до кэшей/таблиц. Отсутствие ready проверяется независимо от исключения.

Реальную функцию `computeSceneAudit` инструментирует тестовый ответ модуля:
подмена одноимённого глобального alias не могла бы измерить нативный вызов.
`check-native-browser.py` отдельно работает вообще без такой инструментализации,
проверяет отсутствие `window.D/cam/caches`, URL всех модулей и два API в разных
документах, использующих один модульный граф. Остановка первого не меняет второй.

## Кеш и ошибки сети

Cache-тесты используют сервер с настоящими HTTP cache headers, **без page.route**:
routing выключил бы кеш и сделал тест недостоверным. Выполняется отрицательный
контроль без новых asset URL, который должен обнаруживать A-модули внутри B-HTML.
Детали, ограничения и обязательная проверка Pages — [deployment-versions.md](deployment-versions.md).

Сбой screenshot не скрывает исходное исключение: JSON сохраняет основную ошибку
и отдельное `screenshot_error`. Если сам сценарий прошёл, но снимок получить не
удалось, набор остаётся красным. Ошибки не превращаются в PASS и не пропускаются.

## Артефакты и сравнение

Положительные обзоры smoke: desktop **1800×1200**, mobile **390×844**, DPR **1**,
`visual`, fit, без выбора. На mobile панель свёрнута. После смены размеров необходимо
дождаться запланированного кадра: ResizeObserver очищает размер Canvas до отрисовки.
Сохраняются PNG/JSON/trace; файлы в `browser-artifacts` исключены из Git.
`summary.json` содержит завершённые случаи, JSON отдельного упавшего случая — ошибку.

При чистом рефакторинге дополнительно сравниваются данные и каждый Canvas-слой
в одинаковой браузерной среде; geometry golden не заменяет визуальное сравнение.
Проверки предоставленного кода в памяти не проверяют HTTP/import cache/Pages
и должны обозначаться отдельно, без смешения со счётчиком HTTP-сценариев.
Headless Chromium с эмулированным touch не подтверждает Safari или физический iPhone.
