# Браузерные проверки

Задача [#30](https://github.com/k911mipt/terraria-base/issues/30) из
[плана рефакторинга #24](https://github.com/k911mipt/terraria-base/issues/24).

## Запуск

Нужен Python 3.10+; Playwright — только зависимость разработки, сайт её не загружает.
Установка в изолированное окружение:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
# Linux: при отсутствии системных библиотек — playwright install --with-deps chromium.
python tools/check-browser.py
```

В CI используется та же последняя команда. Тест сам поднимает HTTP-сервер на свободном
loopback-порту, открывает настоящие HTML и отдельные JS/CSS, закрывает сервер и браузер.
В среде с уже установленным Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.
Выходные артефакты по умолчанию лежат в `browser-artifacts/` (исключено из Git);
другой каталог задаётся через `--artifacts`.

## Что доказывает проверка

Для `index.html`, `desert.html`, `underground.html`, `jungle.html`:

- слушатели исключений и сетевых ошибок установлены **до** навигации;
- `data-ready` появляется у viewport только после завершения startup и успешного
  первого запланированного рендера; статического атрибута в HTML нет;
- таблицы комнат, материалов и объектов заполнены; оба видимых кешированных
  Canvas-слоя содержат реальный разноцветный рисунок, а не пустой фон;
- каждый доступный режим меняет отрисовку; работают фокус, возврат камеры,
  инспектор контрольной двери и пустого тайла, четыре статические вкладки и переход;
- на desktop проверяются мышиное перетаскивание и колесо, на mobile — шторка,
  реальное touch-перетаскивание и двухпальцевый pinch через Chromium CDP;
- на подземной сцене дополнительно проверяются регрессии безопасности стен и
  различие принадлежности двери и географической области её тайла.

Сайт не должен требовать внешней сети: внешние запросы приводят к ошибке.
Необязательный HEAD-probe версии публикации изолирован ответом 204 и записан отдельно;
он не подменяет загрузку обязательных ресурсов.

Ещё 12 сценариев (три мутации для каждой страницы) проверяют тот же startup-gate:
исключение перед startup, 404 startup-JS и 404 основного CSS должны быть отклонены
по ожидаемой причине. В этих сценариях заголовок остаётся на странице; PNG и его
размер не служат признаком успешной инициализации. Мутации существуют только в
изолированном browser context и не записываются в исходники.

Дополнительно 16 сценариев проверяют повреждённые данные материалов до запуска:
неизвестный блок, неизвестная стена, удалённая спецификация и неправильная палитра
в каждой сцене. Помимо ожидаемого исключения независимо проверяются отсутствие
`data-ready`, пустая таблица комнат и видимая диагностика с координатами.
Положительные сценарии также выбирают повреждённый после запуска тайл мышью/touch:
инспектор должен показать ошибку, а не упасть или назвать материал воздухом.
Ещё 16 сценариев отвергают неизвестный kind/style, удалённый рендерер и
не-функцию в реестре до startup. Проверяются видимая диагностика, пустые
таблицы и отсутствие ready независимо от ожидаемого исключения.
[Устройство реестра и Node-регрессии](object-renderers.md).
Ещё 16 сценариев повреждают размеры, комнату, предметную спецификацию и цвет
объекта. Нормальные сценарии проверяют реальные неполные светильники, сундуки,
жидкости/резервы и повреждённую после запуска привязку комнаты, включая tooltip.
[Метаданные и честное отображение неполных спецификаций](object-contract.md).
Итого **68 HTTP-сценариев**. Правила материалов описаны в
[контракте материалов](material-contract.md).

## Артефакты и воспроизводимость

Desktop: **1800×1200**, mobile: **390×844**, DPR **1**, Chromium из закреплённого
Playwright. Итоговый положительный снимок: `visual`, `fit`, без выбора объекта;
мобильная панель свёрнута. Для каждого сценария сохраняются PNG, JSON сетевых/
консольных событий и Playwright trace; `summary.json` содержит завершённые сценарии.
При ошибке workflow сохраняет уже полученную диагностику, но остаётся красным.

```bash
python -m playwright show-trace browser-artifacts/index-desktop-trace.zip
```

Это smoke-test поведения, не универсальный визуальный golden-test: при чистом
рефакторинге отдельно сравниваются исходные и новые снимки **в одной среде** и данные
геометрии/материалов/объектов. Headless Chromium и эмулированный touch не доказывают
работоспособность физического iPhone/Safari или всех устройств. Ручной сценарий
на телефоне: пройти четыре вкладки, свернуть/развернуть шторку, перетащить карту одним
пальцем, увеличить и уменьшить двумя, отпустить один палец, выбрать дверь и пустой
тайл; после pinch не должно появляться случайного выделения.
