# Версия HTML, CSS и нативного графа (#34)

## Механизм

`python tools/version-assets.py --write` вычисляет SHA-256 содержимого всех
runtime/data/entry JS, `js/package.json`, CSS, favicon и четырёх HTML без ранее
сгенерированных штампов. Один токен ставится в CSS/bootstrap URL и import map
**всех** JS, а не только стартового файла. `deployment.json` содержит ту же версию.

Imports остаются обычными относительными ссылками. HTML import map нормализует
их к URL с версией, включая транзитивные зависимости и динамический entry import.
Все четыре вкладки — статические ссылки без JS-зависимости. После изменения
исходников нужно обновить штампы; обычный локальный HTTP-сервер дополнительных
преобразований не выполняет. Повторная генерация идемпотентна.

```sh
python tools/version-assets.py --write
python tools/version-assets.py --check
python tools/check-version-assets.py
python tools/validate.py
python -m http.server 8000 --bind 127.0.0.1
```

Проверка `--check` входит в обязательную общую команду и **не пишет файлы**.
Изменение зависимости или CSS без обновления версии приводит к ошибке.

## Открытая старая страница

Bootstrap проверяет `deployment.json` с `cache: no-store` **до импорта большого
графа**. При новой корректной версии открывает тот же документ с `_v=<версия>`.
Если прокси опять отдаёт старый HTML даже для этого адреса, второго перехода
на ту же версию не будет. Прочие параметры и hash URL сохраняются.

Проверка не использует localStorage, имеет таймаут 2 секунды и не мешает запуску
при offline/HTTP-ошибке/некорректном JSON. Доступность файлов всё равно необходима:
это не Service Worker, не PWA и не обещание открыть ещё не кешированную страницу
без сети. Уже загруженный экземпляр не требует сети для движения/инспектора.

## Что требуется подтвердить

`check-ui-rollout.py` содержит 16 сценариев с настоящим HTTP-сервером и сохранённым
браузерным кешем: для каждой сцены A→B с новым HTML, со старым HTML и отрицательный
контроль без версионирования; дополнительно offline, запрет storage, 503 и
повреждённый JSON. Проверяются данные, отдельный транзитивный модуль рендерера,
CSS, обновление и повторное открытие. Request routing не используется, чтобы не
отключить HTTP-кеш Chromium. Счётчики запросов отдельно доказывают его сохранение.

Токен URL — ключ кеша, **не проверка целостности полученных байтов**. Query-параметр
не хранит исторические копии на GitHub Pages и не обеспечивает транзакционную
загрузку при публикации посреди серии запросов. Для такой гарантии понадобятся
неизменяемые каталоги публикаций с сохранением их файлов. Текущая реализация
устраняет обычное повторное использование старых URL после завершённой публикации;
нельзя объявлять более сильную гарантию только по совпавшим токенам.

#34 нельзя считать закрытой только по Node/офлайн-тестам: нужны успешные реальные
cache-сценарии, проверка фактически опубликованного Pages-артефакта и явное решение
о хранении версий для конкурентной публикации. Эти границы отделены от нативного
состояния и imports задачи #33.
