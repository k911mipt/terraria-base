SHA и открытые PR: этот снимок не разрешает удалять появившуюся после него работу.

## Две ветки с уникальными заглушками

| Ветка | SHA | Единственный уникальный файл | Открытый PR |
| --- | --- | --- | --- |
| `feature/jungle-outpost-actual2` | `945465c05d168aae413735a66bd527ad73634a01` | `docs/.jungle-render-fix` | Нет |
| `feature/jungle-outpost-work` | `3013ccbe1b9e5a591b05e29b78f128e79339e730` | `docs/.jungle-fix-placeholder` | Нет |

Для каждой compare дал `diverged`, `ahead_by: 1`, `behind_by: 4`;
merge-base — `283a888c226ffc251832d1481466b8ed4300b138`.
В diff ровно один добавленный файл, одна строка, без изменений данных сцены,
рендера, HTML, стилей или рабочих проверок.

Оба файла прочитаны по указанным commit SHA. Их **полное содержимое** — строка
`temporary placeholder`, UTF-8, **без завершающего перевода строки**, 21 байт.
Git blob SHA обоих: `226cf458a99bb1f2c834b11dab21e0fd97bc8c67`.
Байты можно восстановить и проверить так:

```bash
printf %s 'temporary placeholder' | git hash-object --stdin
# 226cf458a99bb1f2c834b11dab21e0fd97bc8c67
```

Решение: содержательной незавершённой работы здесь нет; сами заглушки полностью
сохранены в этом отчёте. После попадания отчёта в `main` и повторной сверки refs/PR
эти две ветки также можно удалить. Удаление только по префиксу не применяется.

## Порядок операции

Сначала сохранить и отревьюить отчёт. Затем заново получить ветки и открытые PR.
Удалять только 14 точных имён из таблиц, если их SHA не изменились и PR не появились;
при любом отличии оставить соответствующую ветку. После удаления снова проверить
список и записать результат в PR. `main`, активные и неизвестные ветки не затрагивать,
историю не переписывать, настройки доступа не менять.
