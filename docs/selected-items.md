# Выбранные названия и предметы-носители

Подэтап #27 после структурного контракта #46. Справочники в `validation.js`
проверяют уже выбранные проектом имена, а не просто непустую строку:
`MATERIAL_NAMES`, `OBJECT_ITEM_NAMES` и `KNOWN_PAINTS` — независимые явные наборы.
Они не строятся из текущих D/spec-ов, иначе опечатка разрешала бы сама себя.
Материал блока нельзя назвать стеной, выбранный сундук — оружием или произвольной
строкой; неизвестная краска также является ошибкой. При добавлении нового
выбранного предмета сначала расширяется соответствующий проверенный справочник.

Проверяются обе начатые группы foreground/chest. Старые 240 невыбранных
спецификаций остаются ограниченными ранее зафиксированными исключениями и WARN:
никакие игровые имена/краски вместо них не придуманы. Реестр допустимых исходных
названий не равен полной проверке каталогов игры, версии доступности и рецептов.
Составные названия и альтернативы в старых описаниях сохранены, а не выдаются
за один предмет с таким буквальным названием в игре.

## Экспонат и устанавливаемая мебель

Инспектор отдельно показывает **Носитель** для 53 однозначно описанных экспонатов.
Материал/имя экспоната и подробные описания остаются на месте. Наличие Киркопилы
в рамке не означает установку Киркопилы в качестве переднего блока.

| Носитель | Item ID | Размер |
| --- | --- | --- |
| [Weapon Rack](https://terraria.wiki.gg/wiki/Weapon_Rack) | 2699 | 3×3 |
| [Item Frame](https://terraria.wiki.gg/wiki/Item_Frame) | 3270 | 2×2 |
| [Mannequin](https://terraria.wiki.gg/wiki/Mannequin) | 498 | 2×3 |

Это существовавшие до 1.4.5.6 предметы. Используются только указанные стабильные
идентификаторы и размеры; изменения последующих версий (например, новые предметы,
которые помещаются на стойку) в контракт не включены. Альтернативные способы
крепления рамки не заменяют уже выбранное проектом настенное крепление.
[Краски](https://terraria.wiki.gg/wiki/Paints) проверяются по выбранным проектом
значениям; `None` отличается от отсутствующей спецификации.

Для музейных стойки/рамки/манекена и описанных инструментальных рамок теперь
проверяется размер **носителя**, не размер показанного на нём предмета. Родовое
`display` без выбранного экспоната не превращается автоматически в Item Frame:
личные картины/эмблемы по-прежнему остаются неуточнёнными.

## Проверки

```sh
node tools/check-selected-items.cjs
python tools/validate.py
```

601 отрицательная мутация: подмена непустого названия/краски каждого выбранного
материала и предмета, размеры известных носителей. Проверяются диагностические
ID/координаты и отсутствие изменений D. Дополнительные 16 HTTP-сценариев портят
название блока/предмета и краску стены/предмета до запуска; ready не появляется.
Положительные pointer/touch-сценарии выбирают настоящие рамки, проверяют носитель
и диагностируют неизвестное название после старта. Основной HTTP-набор теперь
содержит 112 сценариев; ещё 8 cache и 16 lighting дают 136 всего.

Вид карты, палитры, координаты, порядок слоёв и geometry golden не меняются.
Этот этап не завершает выбор 240 старых предметов и не подменяет общий строительный
аудит. Полная #27 остаётся открытой для неуточнённых конструктивных свойств.
