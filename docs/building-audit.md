# Вычисляемая проверка конструкции

Этап #28 плана #24. Общие чистые функции находятся в
`js/runtime/building-audit.js`; они не зависят от DOM, Canvas или сохранённого
`D.validation`. Это проверка правил проекта, не симулятор движка Terraria.

```sh
node tools/check-building.cjs
node tools/audit-building.cjs
node tools/audit-building.cjs --json
```

Первая команда проверяет **сам проверяющий код** положительными и отрицательными
примерами. Вторая и третья проверяют **актуальную конструкцию**, печатают все
нарушения и возвращают 1 при наличии ошибки. Успешные регрессии не означают,
что текущая постройка прошла аудит. Старые ошибки не превращаются в исключения.

## Модель

`buildingGrid` использует последнее наложение прямоугольника. Проверка сравнивает
результат с настоящим runtime `rectAt` во всех координатах четырёх сцен.
Платформа отличается от твёрдого блока; Bubble не становится твёрдой опорой.
Проверяются ограниченные целочисленные размеры до перебора тайлов.

`BUILDING_SCENES` явно перечисляет закрытые комнаты, проходы и уровни платформ.
Контекстные биомные области и наружные арены не выдаются за закрытые помещения.
Прямоугольник комнаты включает контур: покрытие проверяется внутри контура,
а двери, люки и платформы — дополнительными правилами на самих границах.

Даже вне комнаты платформа требует стены, если стена продолжается прямо сверху
или снизу. Поэтому намеренно открытый навес без окружающих стен разрешён, а
однострочный разрыв существующего фона не маскируется словом «наружный».

Объекты имеют явные проектные классы крепления: пол, потолок, стена, факел,
самонесущий planter, дверь, люк, встроенный проходной элемент либо непредметный
маркер. Это не доказательство выбранного игрового предмета: неполные предметные
метаданные продолжают отмечаться отдельно в #27. Проверка не угадывает крепление
по цвету и не разрешает произвольный `collision:false` в данных.

Для физического предмета проверяется весь заданный footprint, а не только опора.
Люстра с сохранённой опорой всё равно ошибочна при твёрдом блоке внутри неё.
Для двери нужна хотя бы одна свободная сторона; настенный декор и NPC-маркеры
не блокируют створку. Для люка нужны платформа ровно сверху и твёрдые боковые
опоры на уровне люка. Уровни платформ и явно заданные проходы проверяются отдельно.

## Диагностика и ограничения

Каждая ошибка содержит сцену, правило, координату и ID/имя участка. В JSON также
есть фактические количества эффективных блоков/стен, проверенных фоновых тайлов,
предметов и открываемых дверей. Одинаковая ошибка может затрагивать несколько
тайлов; число сообщений не равно числу независимых игровых дефектов.

На исходной ревизии b3c8fe6 строгая проверка обнаруживает 187 сообщений:
179 в основной базе, 6 в Desert, по одному в Underground и Jungle. Среди них
162 тайла фона наружной босс-арены и нарушения креплений/створок из #42.
Это исходный результат, **не golden ожидаемых ошибок**. Любая будущая правка
пересчитывает отчёт; ни количество, ни статусы не подгоняются ради PASS.

В этом PR геометрия и рисование не меняются. Исправления принятой схемы выполняются
отдельными PR по задаче #42; общий вывод того же результата в UI — следующий этап #29.
