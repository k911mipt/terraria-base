# Явные рендереры тайлов и разделение runtime

Разделение runtime из #55 сохранено; нативная миграция #33 добавляет явные
imports и отдельные реестры каждого экземпляра.

`model.js` содержит только поиск эффективного тайла/объекта и перевод координат.
`render-tiles.js` содержит процедурные текстуры, формы блоков и `TILE_RENDERERS`.
`render-cache.js` проверяет данные и строит три кэша. Весь `inspect()` и tooltip
находятся в `inspector.js`, а не в модуле текстур.

## Выбор функции

`registerTileRenderer(planner, layer, materials, draw)` явно связывает ключи блока/стены
с функцией. Регистрация отвергает неизвестный слой, пустой ключ, не-функцию и
дубликат; неуспешный вызов не добавляет часть ключей. `tileRenderer()` используется
и проверкой, и `tileMaterial()` / `tileWall()`. Список разрешённых ключей не строится
из данных сцены, иначе опечатка разрешала бы сама себя.

Общие текстуры регистрируются один раз для каждого экземпляра. Desert, Underground и Jungle добавляют
только свои ключи. Цепочек сохранения/переопределения `tileMaterial`, `tileWall`
или объектных `draw*` больше нет. Платформы проходят тот же явный диспетчер;
неизвестный материал не получает запасную текстуру кирпича.

До Canvas-кэшей проверяются материалы, тайловые/объектные функции и объекты.
Удалённая функция или не-функция дают видимую диагностику с координатами, пустые
таблицы и отсутствие `data-ready`. Общий вычисляемый аудит получает ошибки обоих
реестров — UI и CLI не могут пропустить отсутствующую тайловую функцию.

## Проверки

```sh
node tools/check-tile-renderers.cjs
python tools/validate.py
```

23 Node-checker-а, включая проверку 86 используемых в четырёх сценах регистраций
и 274 отрицательные мутации. Подмена функции тестовой доказывает точный вызов
зарегистрированной функции с исходным Canvas-контекстом, материалом и координатами.
Отдельно проверяются атомарность регистрации, отсутствие переназначений и startup.

Основной HTTP-набор содержит 144 сценария: добавлены 16 случаев отсутствующей или
неправильной функции тайла. С нативными проверками, cache-rollout и lighting — 184 определения сценариев. Полный состав,
условия снимков и ограничения среды описаны в [browser-tests.md](browser-tests.md).

Порядок слоёв, данные сцен, палитры и независимый geometry golden не изменены.
Процедурные команды рисования сохранены. Вода двух аванпостов пока рисуется своими
функциями: отличающиеся градиенты и пузырьки не объединяются ради количества строк.

## Нативный экземпляр

После миграции #33 реестры находятся в `planner`, функции регистрации/lookup
принимают его первым аргументом. Сценические функции регистрации вызываются
явно из `createPlanner`; imports не имеют регистрационных побочных эффектов.
[Подробности](native-modules.md).
