# Диагностика площадок спавна (#38)

Целевая игра — **Terraria 1.4.5.6**. Это обследование геометрии, не симулятор
спавна и не разрешение перестраивать крышу. Ни блоки, ни жидкости, ни люки,
ни положение предметов этой проверкой не изменяются.

## Запуск

```sh
# Геометрия; численные дистанции по умолчанию НЕ предполагаются.
node tools/audit-spawn-surfaces.cjs
node tools/audit-spawn-surfaces.cjs --json

# Условный сценарий по явно выбранному справочному профилю.
node tools/audit-spawn-surfaces.cjs --profile wiki-1.4.5 --player 9,51
node tools/audit-spawn-surfaces.cjs --profile wiki-1.4.5 --player 9,51 --player 126,51 --json

# Явно исключённая поверхность остаётся в отчёте с отметкой EXCLUDED.
node tools/audit-spawn-surfaces.cjs --exclude combat-street

# Опциональный раздел общего аудита; регрессии входят в validate.py.
node tools/audit-scene.cjs --spawn --json
node tools/check-spawn-surfaces.cjs
python tools/validate.py
```

`--player X,Y` — целочисленная координата **тайла верхнего левого угла хитбокса**,
не центр, не ноги и не координата курсора. Поддерживаются один или два игрока;
без аргумента записывается `(67,51)`, но дистанции всё равно не вычисляются без
`--profile`. Координаты мирового сохранения нужно перевести в систему плана.

Код возврата 0 означает успешное выполнение диагностики, **не отсутствие спавна**.
Неправильные входные данные дают ненулевой код. Итог диагностики всегда
`NOT_VERIFIED`: общий строительный аудит сохраняет собственный независимый статус.

## Источники и граница достоверности

Проверены 17 сентября 2026:

- [NPC spawning](https://terraria.wiki.gg/wiki/NPC_spawning#Choosing_a_spot_to_spawn_the_NPC):
  выбор начального тайла, поиск опоры вниз, проверка пространства 2×3 и участие
  нескольких игроков. **На странице открыто требование актуализировать пороги
  и порядок проверок для 1.4.5**; старые числа не принимаются за проверенные для 1.4.5.6.
- [Guide:Enemy farming](https://terraria.wiki.gg/wiki/Guide:Enemy_farming#Spawn_location):
  отдельно описаны вертикальные расстояния 1.4.5 — вверх/вниз 52/51 для появления
  и 39/38 для внутренней области. Справочный профиль использует их вместе с
  горизонтальными 84/83 и 62/61 из описания обычного спавна. Это **приближение
  по wiki**, а не проверка исполняемого файла 1.4.5.6.
- [1.4.5.6](https://terraria.wiki.gg/wiki/1.4.5.6): граница целевой версии.
  Отсутствие изменения в перечне исправлений не доказывает неизменность алгоритма.

Таким образом, справочный профиль включается только явно. Он не моделирует
дополнительные пиксельные проверки относительно хитбоксов всех игроков, экипировку
для изменения обзора, секретные сиды, конкретное нашествие или виды противников.
Для точного заключения нужны проверка в мире этой версии и параметры реального
сценария. Летающие, телепортирующиеся, призванные и порождённые статуями NPC здесь
не проверяются. Городские NPC и факелы не используются как доказательство запрета.

## Что рассчитывается

`tools/lib/spawn-surfaces.mjs` переиспользует `buildingGrid`: поздние прямоугольники
перекрывают ранние в том же порядке, что и в runtime. Для каждой опоры проверяется
прямоугольник `X−1…X, Y−3…Y−1`. Полный блок в нём отмечается `blocked`; отсутствие
опоры — `no-ground`. Платформы, скосы, проходные/актуированные блоки, жидкости и
неизвестные тайлы получают `unknown`, а не ошибочно гарантированный запрет.
Процедурные спрайты мебели не превращаются в тайлы, блокирующие спавн.

По явному справочному профилю проверяются внешнее окно, объединение внутренних
окон игроков и доступные начальные тайлы над опорой. Стена отвергает **начальный**
тайл, а не автоматически весь столбец. Твёрдое препятствие прерывает путь от
вышележащих начальных тайлов; свободный тайл ниже препятствия остаётся отдельным
кандидатом. Поиск ограничен известной геометрией и внешним окном профиля.
Если необходимая область уходит за границы схемы, результат не подменяется воздухом.
Границы схемы — **не границы мира**.

`reference-candidate` обозначает только наличие пути в этой модели. Остальные
`range`-статусы также относятся к профилю, а не гарантируют игровую безопасность.
Соседние одинаковые результаты группируются; поле `seed` — один пример для группы.

## Исходные результаты на 50d69d5

Явно обследуются крыши `X9…44/Y27`, `X91…126/Y27` и разрешённая боевая улица
`X1…134/Y54`. Крыши действительно есть в текущей модели; их наличие не означает,
что все перечисленные клетки подходят для спавна.

Из 72 координат двух крыш **62** имеют полную опору и пустое справочное пространство
2×3; **6** заняты платформами и требуют уточнения; у **4** пространство пересекает
твёрдый блок. Это вычисленные геометрические категории, **не 62 подтверждённых
игровых места спавна**. При игроке `(9,51)` профиль wiki отмечает условного кандидата
`X92/Y27` с примером начального тайла `X92/Y26`; при другом положении результат
меняется. По умолчанию такой дистанционный вывод не делается.

Лава, перекрытие люков и перестройка крыши не применяются автоматически.
Дальнейшее решение о конструкции должно опираться на игровой эксперимент.
