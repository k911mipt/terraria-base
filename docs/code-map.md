# Карта исходного кода

Промежуточное состояние [плана #24](https://github.com/k911mipt/terraria-base/issues/24).
Статический Canvas-сайт, без сборщика и runtime-зависимостей. Используются
нативные `import/export`, явные entry points и состояние экземпляра планировщика.

## Данные и точки входа

| HTML | Данные | Расширение отрисовки |
| --- | --- | --- |
| `index.html` | `js/data/` | Общие функции |
| `desert.html` | `js/data/desert/` | `js/runtime/desert-extensions.js` |
| `underground.html` | `js/data/underground/` | `js/runtime/underground-extensions.js` |
| `jungle.html` | `js/data/jungle/` | `js/runtime/jungle-extensions.js` |

`layout.js` содержит границы/комнаты, `solids` — передний слой, `backgrounds` — фон,
`objects` — предметы, NPC и маркеры, `engineering` — устройства и цепи.
Основная база разбита на тематические подкаталоги; `index.js` сохраняют явный
порядок сборки. В `backgrounds/boss-platform-joins.js` — намеренные соединения
существующих стен за платформами, а не автоматическая починка при запуске.

`js/boot.js` выбирает entry из HTML после ограниченной проверки версии.
`js/entries/*.js` импортируют свою `createScene()` из `js/scenes/` и общий `startPlanner`.
Фабрики палитр и клон данных отделяют экземпляры и аванпосты.

`D.sceneId` стабилен; `D` — модель сцены, `ENG` — инженерная модель.
Общие `materials.js` и сценические справочники содержат палитры и спецификации.
Порядок прямоугольников/объектов является частью модели: последние наложения
побеждают. Данные сундуков включают подробные `look/loot/avoid/policy` и не сокращаются.
`designHistory` — историческая запись, не результат проверки текущих данных.

## Runtime

| Файл в `js/runtime/` | Ответственность |
| --- | --- |
| `scene-ui.js` | Явные режимы, фокус, таблицы и инженерные возможности сцен |
| `state.js` | `createPlannerState`: собственные DOM/Canvas, камера, история, выбор, кэши и реестры |
| `events.js`, `lifecycle.js` | Собственные слушатели/таймеры, ResizeObserver и идемпотентное освобождение |
| `deployment.js` | Ограниченная проверка manifest перед импортом entry, без storage |
| `core.js` | Координаты, цвета, планирование кадра, `roomAt` и `roomForObject` |
| `model.js` | Эффективный тайл/объект и перевод координат; без рисования и UI |
| `render-tiles.js` | Процедурные текстуры, формы блоков, реестр block/wall → функция |
| `render-cache.js` | Проверки перед рисованием и построение трёх кэшей |
| `render-base.js` | Структурные слои, объединение кадра, общие элементы |
| `render-objects.js` | Объекты и явный реестр пар kind/style → функция |
| `*-extensions.js` | Процедурные текстуры и зарегистрированные объекты аванпостов |
| `overlay.js` | Инженерные индексы, устройства, провода, подписи и поиск |
| `inspector.js` | Основной `inspect()`, спецификации выбранного тайла и tooltip |
| `formatters.js`, `tables.js` | Форматирование и общие таблицы по настройкам сцены |
| `camera.js`, `interactions.js` | Камера, поиск, кнопки, pan, wheel, pointer/touch/pinch, шторка |
| `prepare.js`, `start.js` | Общая подготовка/запуск; отдельных startup-файлов аванпостов нет |
| `validation.js` | Контракты материалов/объектов, непредметные роли, старые исключения и проверка ям |
| `placement-contract.js` | Привязки материалов, идентичность установки, общие крепления и проходимость |
| `building-audit.js` | Проверки эффективной конструкции по общему контракту |
| `lighting-audit.js` | Общая проектная эвристика света и её представление |
| `scene-audit.js` | Единый вычисляемый результат для UI и CLI |

`roomForObject` предпочитает явную комнату; `roomAt` — географическую область.
Инспектор показывает оба понятия. Неизвестная ссылка диагностируется, а неполный
предмет не называется воздухом. Безопасная/небезопасная/отсутствующая/неописанная
стена — разные состояния. Синтетический инженерный overlay отделён от предметов D.

`data-ready` выставляется только после startup и успешного кадра. Материалы,
регистрация рендереров и структура объектов проверяются до кешей/таблиц.
Тайловые и объектные диспетчеры не подменяются. Расширения явно регистрируют
свои ключи; модель, текстуры, кэши и инспектор разделены. Stateful-функции принимают
`planner` явно; импортированные функции не переназначаются. [Жизненный цикл](native-modules.md). [Рендереры тайлов](tile-renderers.md).
Четыре вкладки статические. [Одна версия графа/CSS](deployment-versions.md)
генерируется `tools/version-assets.py` и проверяется без записи; реальный rollout
и гарантии конкурентной публикации #34 проверяются отдельно.

## Проверки и документы

Полная команда — `python tools/validate.py`, список — с `--list`. Она обнаруживает
JS/CJS для синтаксиса и все Node checker-ы, проверяет release stamps, затем запускает строгие аудиты и четыре
HTTP-набора. `check-validation.py` проверяет сам runner. Единственный read-only
workflow — `validate-browser.yml`; check — `validate`. Старые Jungle-workflow удалены,
существующая публикация Pages сохранена. [CI, окружение и границы защиты main](validation.md).

`tools/lib/load-scene.cjs` загружает настоящий ESM-entry из `data-planner-entry`
через Node.js 22; VM исполняет только тестовые мутации, не исходники приложения.
`load-audit.cjs` использует те же определения и независимое состояние без DOM. Geometry golden независим
от `designHistory` и вычисляемого PASS; его нельзя обновлять ради зелёного CI.
