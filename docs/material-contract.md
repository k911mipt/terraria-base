# Проверяемый контракт материалов

Первый самостоятельный этап [#27](https://github.com/k911mipt/terraria-base/issues/27)
из плана [#24](https://github.com/k911mipt/terraria-base/issues/24).

`validateUsedMaterialSpecs()` в `js/runtime/validation.js` — чистая проверка,
общая для CLI и runtime. Проверяются используемые передние материалы и фоновые
стены всех четырёх сцен: собственные записи спецификаций и палитр, непустые
`itemRu`, `itemEn`, `paintRu`, `paintEn`, `note`, допустимый `layer` переднего
слоя, обязательный boolean `safe` стены, целочисленные упорядоченные границы.
`safe: false` допустимо и не подменяется безопасной стеной.

Палитра блока — объект с `base`, `dark`, `light`; стены — массив ровно из двух
цветов. Поддержан используемый проектом формат `#RRGGBB` и `rgba(r,g,b,a)`.
Неизвестный материал, отсутствующее поле или неверный формат не маскируются
запасной текстурой. Имена вроде `__proto__` не берутся из прототипа словаря.

`buildBaseCaches()` проверяет данные до отрисовки. При ошибке готовность сцены
сбрасывается, инспектор показывает материал, сцену, координаты и причину, запуск
завершается исключением. `inspectorMaterialSpec()` использует те же правила:
повреждённые после запуска данные показываются диагностикой без `TypeError`.
Отсутствие стены/блока остаётся отдельным состоянием, не ошибкой спецификации.

## Проверки

```sh
node tools/check-materials.cjs
python tools/check-browser.py
```

Первая команда проверяет реальные данные, каждое обязательное поле каждого
используемого материала, ошибки палитр, унаследованные записи, прямоугольники,
допустимые наложения и отсутствие изменения данных. Любая неожиданная ошибка
или пропущенная отрицательная мутация завершает её ненулевым кодом.

HTTP smoke включает 80 сценариев: восемь desktop/mobile, 12 с сорванным запуском
или 404, 16 с повреждёнными материалами, 16 с повреждённым реестром отрисовки и 28 с повреждёнными объектами. Для материальных мутаций независимо
проверяются отсутствие `data-ready`, пустая таблица комнат, исключение и видимая
диагностика. Нормальные сценарии также выбирают повреждённый после запуска тайл
настоящими pointer/touch-событиями, затем восстанавливают данные.

## Границы

Это не завершение всей #27 и не новый каталог предметов Terraria. Проверка
подтверждает наличие структурированных имён материала, но не сверяет произвольное
непустое имя с игрой. Ещё предстоят предметный контракт объектов и разбор неполных старых описаний.
[Реестр рендереров](object-renderers.md) уже проверяет допустимые пары kind/style. Открытые области без стен и
last-write-wins наложения разрешены; покрытие закрытых комнат и крепления относятся
к #28. Сохранённые утверждения `D.validation` заменяются отдельно в #29.
Геометрия, палитры и описания этим этапом не меняются.
