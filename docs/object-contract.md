# Метаданные объектов и неполные спецификации

Подэтап #27 из #24, после материального контракта и реестра рендереров.
`js/runtime/validation.js` содержит небольшой адаптер существующих записей,
а не новый каталог Terraria. Массивы данных и описания не переписываются.

## Что означает элемент

Отдельно различаются обычный предмет, зона, NPC-маркер, жидкость, будущий
резерв, ландшафт и эскиз декора. Классификация относится к текущим типам
планировщика: `teleporter` сейчас означает резерв; `jungle_canvas`,
`jungle_totem` и `jungle_plant` — эскизы без выбранного реального предмета.
Добавление настоящего устанавливаемого телепорта или конкретной декорации
потребует соответствующего уточнения контракта, а не повторного использования
резервного типа под видом обычной мебели.

Предметная запись с `foreground*` приоритетна. При её отсутствии переиспользуется
существующая `chest*`-спецификация. Любая начатая группа должна содержать непустые
`ItemRu`, `ItemEn`, `PaintRu`, `PaintEn`; частичная foreground-группа не скрывается
полной chest-группой. Проверяются обе группы, когда заданы обе.

Реальный объект без спецификации **не называется воздухом**: инспектор показывает
«Объект · неполная спецификация», «Предмет не указан» и «Краска не указана».
Явное `None` сохраняет значение «Без краски», но не подставляется вместо отсутствия
данных. Известные имена, краски и содержательные описания сохраняются полностью.

Жидкости, маркеры и резервы получают отдельную строку роли, не заменяя информацию
об эффективном переднем блоке выбранного тайла. Эскиз не выдаётся за устанавливаемый
игровой предмет. Неправильная привязка комнаты диагностируется в инспекторе и
tooltip, а чистая `roomForObject()` по-прежнему строго отвергает неизвестную ссылку.

## Проверки и границы

```sh
node tools/check-objects.cjs
python tools/check-browser.py
```

`validateObjectData(scene)` общий для CLI и startup: собственные ID/имя/тип/стиль,
уникальность ID, целочисленный положительный footprint, корректная комната, полнота
явно заданных групп спецификации, формат используемых индивидуальных цветов.
Ошибки содержат сцену, ID и координаты. До рисования/таблиц они отклоняются видимой
диагностикой без `data-ready`.

Отсутствие всей предметной группы в старой записи пока даёт **предупреждение**,
не выдуманный предмет и не подтверждение правильности установки. Текущих таких
записей 240: 169 в основной базе, 23 в Desert, 19 в Underground, 29 в Jungle.
CLI выводит их число; при выборе такого объекта UI показывает недостающие данные.
Новые ошибки частичных групп, ссылок, размеров и цветов являются ошибками, не WARN.

9 497 отрицательных мутаций покрывают реальные записи всех четырёх сцен.
Проверки не меняют D и отдельно проверяют отсутствие подстановки воздух/None,
приоритет foreground/chest и отказ до Canvas. HTTP smoke содержит 68 сценариев,
включая новые 16 стартовых поломок и pointer/touch-проверки реального инспектора.

Это **не завершение всей #27**: проверка непустого имени не сверяет его с игрой,
конкретные предметы/краски для старых записей ещё не выбраны, способ крепления
и проходимость не выводятся из внешнего вида. Обнаружение конструктивных нарушений
относится к #28, единый вычисляемый аудит — к #29. Отдельные схемы не исправляются
ради зелёного результата; текстуры, геометрия и порядок слоёв не меняются.
