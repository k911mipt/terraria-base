# Нативные модули и состояние экземпляра (#33)

HTML подключает один `js/boot.js`. После проверки версии он импортирует явную
точку входа `js/entries/{main,desert,underground,jungle}.js`. Зависимости заданы
нативными `import/export`; скрытого порядка десятков classic scripts больше нет.
Сборщика, транспилятора, runtime-зависимостей и интерпретатора исходного кода нет.

## Создание и остановка

```js
import { createScene } from './js/scenes/desert.js';
import { registerDesertRenderers } from './js/runtime/desert-extensions.js';
import { startPlanner } from './js/runtime/start.js';

const api = startPlanner({
  scene: createScene(),
  registerRenderers: registerDesertRenderers,
  document,
});
api.fit();
// При удалении документа/планировщика:
api.destroy();
```

Один документ предоставляет один набор DOM-узлов с прежними ID. Два экземпляра
могут использовать разные документы, например iframe: модульный граф общий,
но камера, выбор, история, жесты, таймеры, реестры и Canvas-кэши не разделяются.
Это не API для нескольких наборов одинаковых ID в одном документе.

`createPlannerState` клонирует входные данные. `createScene` создаёт независимые
материалы: расширение палитры одного аванпоста не изменяет другую сцену.
`createPlanner` регистрирует общую и сценическую отрисовку. Stateful-функции
принимают `planner` явно; чистые функции геометрии и аудита работают без DOM.

`destroyPlanner` идемпотентен: снимает ready, удаляет слушателей, отключает
ResizeObserver, отменяет кадры/таймеры, освобождает pointer capture и размеры
кэшей, очищает реестры. Уже поставленные callbacks учитывают `destroyed`.
При исключении запуска также выполняется очистка. Данные экземпляра не
публикуются в `window`; событие документа `planner-started` передаёт готовый API.

## Отрисовка

`render-tiles`, `render-objects` и расширения регистрируют callbacks в реестрах
экземпляра. Проверка и рисование обращаются к тем же реестрам. Импортированные
функции не переназначаются. Процедурные инструкции, цвета, порядок наложения и
описания сохранены; геометрический golden этой миграцией не изменяется.

`model.js` отвечает за эффективные тайлы/объекты, `render-cache.js` — за кэши,
`inspector.js` — за inspect/tooltip. Сценические фабрики не загружают чужие
prepare/start, общие функции запуска находятся в `start.js`.

## Проверки

`tools/lib/load-scene.cjs` загружает **реальные ES-модули** через Node.js 22 и
создаёт изолированное состояние. VM оставлен только для коротких существующих
тестовых мутаций: production-код не склеивается и imports не удаляются.

`check-native.cjs` проверяет независимость экземпляров, отсутствие глобального
состояния, очистку и задержанные callbacks. Остальные Node-checker-ы сохранены.
`check-native-browser.py` открывает реальные HTTP-страницы без compatibility
aliases, проверяет модульные URL, настоящий выбор мышью/touch и два экземпляра.

Существующий HTTP smoke использует **только в ответах тестового сервера**
`tools/lib/browser-probe.mjs`, чтобы сохранить старые короткие тестовые выражения.
Реальный `startPlanner` получает испорченные данные до проверки/рендера; это не
hook рабочего сайта. Проверка отсутствия повторного аудита инструментирует
реальную импортированную функцию, а не бесполезную копию в `window`.
Ни один production entry не импортирует файлы `tools/`.

Полная команда — `python tools/validate.py`. Офлайн-сравнение карт полезно для
рефакторинга, но не доказывает HTTP-доставку модулей. Перед merge обязательны
актуальные CI/review, после merge — проверка Pages. Версионирование описано в
[deployment-versions.md](deployment-versions.md).
